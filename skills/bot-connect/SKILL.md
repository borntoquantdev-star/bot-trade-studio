# ขั้นที่ 4 — เชื่อมต่อข้อมูลและโบรกเกอร์

## ขั้นที่ 0 — รู้ก่อนว่าเอ็กซ์เชนจ์ไหน ห้ามเดา

**ก่อนพูดเรื่อง API key แม้แต่คำเดียว** ให้หาคำตอบว่าผู้ใช้จะเทรดที่ไหน

1. อ่าน `bot/profile.yaml` และ `bot/strategy.yaml` ก่อน — ถ้ามีคำตอบอยู่แล้ว
   ให้**ทวนกลับเพื่อยืนยัน** ไม่ใช่ถามใหม่ เช่น "ตามสเปคคุณจะเทรด Hyperliquid ใช่ไหม"
2. ถ้ายังไม่มี ให้ถามเป็นคำถามแรกของขั้นนี้ แล้วค่อยทำอย่างอื่นต่อ

> ❌ **ห้ามถามว่า "มี API key ของ Binance testnet แล้วหรือยัง" ถ้าผู้ใช้ไม่เคยบอกว่าใช้ Binance**
> เอ็กซ์เชนจ์แต่ละที่มีรูปแบบกุญแจคนละแบบสิ้นเชิง ถามผิดที่ = สอนผิดตั้งแต่ต้น
> และทำให้ผู้ใช้ไปสมัครบัญชีที่เขาไม่ได้จะใช้

ขั้นตอนที่เหลือในไฟล์นี้ให้อ่าน**เฉพาะส่วนที่ตรงกับเอ็กซ์เชนจ์ที่ได้คำตอบมา**

| เอ็กซ์เชนจ์ | อ่านต่อที่ | รูปแบบกุญแจ |
|---|---|---|
| **Hyperliquid** | `references/hyperliquid.md` (อ่านก่อนทำอย่างอื่น) | master address + API wallet key |
| Binance / Bybit / OKX และ CEX อื่น | ไฟล์นี้ ส่วน "กุญแจแบบ API key + secret" | API key + secret + สิทธิ์ |
| หุ้น / TFEX / ฟอเร็กซ์ | ไฟล์นี้ ส่วนข้อมูลตลาด + API ของโบรกนั้น | แล้วแต่โบรก |

## กฎความปลอดภัยที่ต้องบอกผู้ใช้ก่อนทำอย่างอื่น

> **กุญแจที่ถอนเงินได้ = ยกบัญชีให้คนอื่น**
> ถ้าเครื่องโดนแฮก หรือกุญแจหลุดไปอยู่ใน git เงินหายได้ทันทีและเอาคืนไม่ได้

### ใช้กับทุกเอ็กซ์เชนจ์ — 3 ข้อ

1. **ที่เก็บ** — อยู่ใน `bot/.env` เท่านั้น และ `.env` ต้องอยู่ใน `.gitignore` **ก่อน**ที่จะสร้างไฟล์
2. **ห้ามพิมพ์ค่ากุญแจออกหน้าจอ** ไม่ว่ากรณีใด ถ้าต้องยืนยันว่าตั้งถูก ให้แสดงแค่ 4 ตัวท้าย
3. **แยกกุญแจของ testnet กับ live** คนละอัน ไม่ใช้ปนกัน

### ถ้าเป็น Hyperliquid (หรือ DEX ที่ใช้ API wallet)

ไม่มีเรื่อง "สิทธิ์ของ key" ให้ตั้งเลย เพราะออกแบบมาต่างกัน — อ่าน `references/hyperliquid.md`
สรุปสั้น: สร้าง **API wallet** ที่ app.hyperliquid.xyz/API แล้วเก็บสองค่าคนละหน้าที่

- `account_address` = บัญชีแม่ ใช้ query ยอดเงินและ position
- `api_wallet_key` = private key ของ agent ใช้เซ็นคำสั่งอย่างเดียว **ถอนเงินไม่ได้โดยธรรมชาติ**

ห้ามเอา address ของ agent ไป query (ตลาดจะตอบสถานะว่างโดยไม่แจ้ง error)

### ถ้าเป็นกุญแจแบบ API key + secret (Binance, Bybit, OKX...)

1. **สิทธิ์ที่เปิด** — เปิดแค่ `read` + `spot trade` (หรือ `futures trade` ถ้าจำเป็น) **ปิด `withdraw` เสมอ**
2. **IP whitelist** — ผูกกุญแจกับ IP ของเครื่องที่รันบอท

เพิ่ม `.gitignore` ก่อนเสมอ:
```
bot/.env
bot/.env.*
*.key
```

## ส่วนที่ 1 — ข้อมูลตลาด

### เลือกแหล่งตามตลาด

| ตลาด | ข้อมูลย้อนหลัง | ข้อมูลสด | หมายเหตุ |
|---|---|---|---|
| คริปโต perp | **Hyperliquid** `candles_snapshot` (ฟรี ไม่ต้องมีคีย์) | WebSocket | ขั้นต่ำ $10/ไม้ มี testnet แยก · อ่าน `references/hyperliquid.md` |
| คริปโต spot | Binance klines (ฟรี ย้อนถึง 2017) | WebSocket | ข้อมูลย้อนหลังยาวที่สุด |
| หุ้นสหรัฐ | Alpaca, Polygon, Yahoo | WebSocket | ข้อมูลคุณภาพดีที่สุด ต้องระวัง split/dividend |
| หุ้นไทย | SETSMART, ข้อมูลโบรก | ส่วนใหญ่ต้องซื้อ | หายากที่สุด เตรียมใจเรื่องค่าใช้จ่าย |
| TFEX | ข้อมูลโบรก | ผ่าน API โบรก | ต้องจัดการ rollover สัญญา |
| ฟอเร็กซ์ | MT5 history, Dukascopy | MT5 / FIX | spread ต่างกันตามโบรกมาก |

### ตรวจคุณภาพข้อมูลก่อนใช้ — 6 ข้อ ห้ามข้าม

ข้อมูลเสียทำให้ backtest สวยเกินจริง แล้วเงินจริงหายทีหลัง

1. **ช่องว่าง (gaps)** — มีแท่งหายไปไหม ตลาดปิดหรือข้อมูลขาด
2. **แท่งวอลุ่มเป็นศูนย์** — มักแปลว่าข้อมูลถูกเติมขึ้นมาเอง ไม่ใช่การซื้อขายจริง
3. **ราคาผิดปกติ (spike)** — แท่งที่กระโดดเกิน 20 เท่าของ ATR ปกติ ต้องตรวจว่าจริงหรือเสีย
4. **โซนเวลา** — ทุกอย่างต้องเก็บเป็น UTC แล้วค่อยแปลงตอนแสดงผล ข้อมูลคนละโซนเวลาปนกันคือฝันร้าย
5. **การปรับราคา (หุ้น)** — ถ้าไม่ปรับ split และปันผล กราฟจะมีช่องว่างปลอมที่กลยุทธ์ breakout จะหลงเข้าไปเทรด
6. **อคติผู้รอดชีวิต (survivorship bias)** — ถ้ารายชื่อหุ้น/เหรียญที่ทดสอบมีแต่ตัวที่ยังอยู่ทุกวันนี้ ผลทดสอบจะดีเกินจริงมาก ต้องรวมตัวที่ตายไปแล้วด้วย

รายงานผลตรวจเป็นตารางให้ผู้ใช้ดู พร้อมบอกว่าข้อไหนจะทำให้ backtest หลอกตา

## ส่วนที่ 2 — โบรกเกอร์

### ไล่ตามลำดับนี้เสมอ ห้ามข้าม

```
1. testnet / sandbox   →  พิสูจน์ว่าส่งคำสั่งได้ ไม่ใช้เงินจริง
2. paper (เงินปลอม ตลาดจริง)  →  ขั้นที่ 6
3. live เงินจริงจำนวนน้อย     →  ขั้นที่ 7
4. live เต็มจำนวน             →  หลังผ่านขั้น 8 อย่างน้อย 3 เดือน
```

### สิ่งที่ต้องตั้งให้ถูกในส่วนนี้

- **ชนิดคำสั่ง** — ใช้ `limit` เป็นค่าตั้งต้น ไม่ใช่ `market`
  คำสั่ง market ในตลาดสภาพคล่องบางจะได้ราคาแย่มาก และ backtest ไม่เคยจำลองตรงนี้ได้ดี
- **กุญแจกันสั่งซ้ำ (idempotency / client_order_id)** — ทุกคำสั่งต้องมีรหัสไม่ซ้ำที่เราสร้างเอง
  ถ้าเน็ตหลุดตอนส่ง แล้วบอทส่งใหม่ เอ็กซ์เชนจ์จะรู้ว่าเป็นคำสั่งเดิม **ไม่มีสิ่งนี้ = เปิดไม้ซ้อนสองเท่าได้**
- **กระทบยอด (reconcile)** — ทุก 30 วินาที ถามเอ็กซ์เชนจ์ว่า "ตอนนี้ฉันถืออะไรอยู่จริงๆ" แล้วเทียบกับที่บอทคิดว่าถือ
  ถ้าไม่ตรง → หยุดทันที แจ้งเตือน ห้ามเดาเอง
- **เพดาน slippage** — ถ้าราคาที่ได้ต่างจากที่ตั้งใจเกินค่าใน `strategy.yaml` ให้ยกเลิก ไม่ใช่ไล่ราคา
- **จัดการ rate limit** — นับโควต้า API ไว้ ถ้าใกล้เต็มให้ชะลอ ไม่ใช่ยิงจนโดนแบน

### ทดสอบการเชื่อมต่อ 4 ข้อ ก่อนบอกว่าเสร็จ

1. ดึงยอดเงินในบัญชีได้ (พิสูจน์ว่า key อ่านได้)
2. ส่งคำสั่ง limit ขนาดเล็กที่สุดในราคาที่ไม่มีทางแมตช์ แล้ว **ยกเลิกได้** (พิสูจน์ว่าสั่งได้)
3. ดึงรายการโพซิชันปัจจุบันได้ (พิสูจน์ว่า reconcile ทำงาน)
4. ลองส่งคำสั่งที่ผิดกติกา (เช่น ขนาดต่ำกว่าขั้นต่ำ) แล้วดูว่าบอทจับ error ได้ ไม่ใช่เงียบหาย

## ผลลัพธ์ที่ต้องส่งมอบ

1. เขียน `bot/connection.yaml` (ไม่มีค่า key ในนั้น)
2. สร้าง `bot/.env.example` ที่มีแต่ชื่อตัวแปร ไม่มีค่า
3. ยืนยันว่า `.gitignore` ครอบคลุม `.env` แล้ว
4. รายงานผลตรวจคุณภาพข้อมูลเป็นตาราง
5. รายงานผลทดสอบการเชื่อมต่อ 4 ข้อ
6. อัปเดต `bot/STATUS.md` แล้วชวนไป `/bot:backtest`
