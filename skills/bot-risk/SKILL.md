# ขั้นที่ 3 — กติกาความเสี่ยง (ห้ามข้าม)

> กลยุทธ์ตัดสินว่าได้กำไรเท่าไหร่ **กติกาความเสี่ยงตัดสินว่ารอดหรือไม่รอด**
> บอทที่กลยุทธ์ธรรมดาแต่คุมความเสี่ยงดี อยู่รอดนานกว่าบอทกลยุทธ์เทพที่ไม่คุมเสมอ

## สิ่งที่ต้องยึดตลอดขั้นนี้

กติกาพวกนี้จะกลายเป็น **risk engine ที่ไม่มี LLM อยู่ในนั้นเลย** เป็นฟังก์ชันคำนวณตรงๆ ที่เทสต์ได้ 100%
LLM เสนอสัญญาณได้ แต่ต้องผ่านด่านนี้เสมอ และด่านนี้ปฏิเสธได้โดยไม่ต้องขออนุญาตใคร

---

## 1. ขนาดไม้ (position sizing)

ถามว่า **"ไม้เดียวที่ผิดทาง คุณยอมเสียกี่เปอร์เซ็นต์ของพอร์ต"** แล้วแปลงเป็นเงินจริงให้เขาเห็น

| ประสบการณ์ | แนะนำ | เหตุผล |
|---|---|---|
| มือใหม่ | **0.25–0.5%** | แพ้ติดกัน 20 ไม้ยังเหลือพอร์ต 90% |
| เคยเทรดบ้าง | 0.5–1% | |
| มีระบบที่พิสูจน์แล้ว | 1–2% | |
| เกิน 2% | **ห้าม** ให้เตือนว่าแพ้ติดกัน 10 ไม้ = หายไปเกิน 20% |

**สูตรที่ต้องใช้ (fixed fractional)**

```
ระยะเสี่ยงต่อหน่วย = | ราคาเข้า − ราคา stop |
เงินที่ยอมเสีย     = เงินทุนปัจจุบัน × risk_per_trade_pct / 100
ขนาดไม้            = เงินที่ยอมเสีย / (ระยะเสี่ยงต่อหน่วย × มูลค่าต่อจุด)
```

จากนั้น **ตัดเพดานซ้ำ** ด้วย `max_position_pct` เสมอ — ถ้า stop แคบมาก สูตรจะให้ขนาดไม้ใหญ่เกินจริง

รายละเอียดและตัวอย่างคำนวณทีละขั้นอยู่ใน `references/sizing.md`

## 2. เพดานขาดทุน 3 ชั้น

ต้องมีครบทั้งสามชั้น ชั้นเดียวไม่พอ

| ชั้น | ค่าแนะนำ | เกิดอะไรขึ้นเมื่อถึง |
|---|---|---|
| **ต่อวัน** | 2% | หยุดเปิดไม้ใหม่จนถึงเที่ยงคืน ไม้เดิมยังบริหารตามปกติ |
| **ต่อสัปดาห์** | 5% | หยุดถึงวันจันทร์ |
| **ขาดทุนสะสมจากจุดสูงสุด (max drawdown)** | ไม่เกินที่ผู้ใช้ตอบใน profile.yaml | **KILL SWITCH** — ปิดทุกโพซิชัน หยุดถาวร รอมนุษย์ปลดล็อกด้วยมือ |

> ย้ำกับผู้ใช้ว่า kill switch **ไม่ปลดล็อกเอง** ไม่ว่าตลาดจะดูดีแค่ไหน
> เหตุผล: ถ้าบอทขาดทุนถึงเพดาน แปลว่าสมมติฐานบางอย่างผิด ต้องให้คนมาดูก่อน

## 3. เพดานการกระจุกตัว

- **จำนวนไม้พร้อมกันสูงสุด** — ถ้าทุกไม้ชน stop พร้อมกันต้องยังรับไหว
  เช็ค: `max_concurrent_positions × risk_per_trade_pct` ต้องไม่เกิน `max_daily_loss_pct`
  ถ้าเกิน ให้บอกผู้ใช้ว่าตัวเลขขัดกันเอง และเสนอตัวเลขที่สอดคล้อง
- **การกระจุกในสิ่งที่วิ่งตามกัน (correlation)** — BTC ETH SOL ขึ้นลงพร้อมกัน ถือ 3 ตัวไม่ใช่กระจายความเสี่ยง แต่คือไม้เดียวขนาด 3 เท่า
  ตั้ง `max_correlated_exposure_pct` และนิยามกลุ่มให้ชัด
- **เพดาน leverage** — มือใหม่ควรเป็น 1 (ไม่ใช้เลย) ถ้าผู้ใช้อยากได้มากกว่า ให้คำนวณราคา liquidation ให้เขาดูเป็นตัวเลขจริงก่อน

## 4. หน้าต่างเวลาที่อนุญาตให้เทรด

- โซนเวลาอ้างอิง (เขียนให้ชัด ปกติ `Asia/Bangkok` แต่ข้อมูลตลาดเก็บเป็น UTC)
- ช่วงห้ามเทรด: ก่อน/หลังข่าวใหญ่, ช่วงสภาพคล่องบาง (คริปโตช่วงเช้ามืดวันอาทิตย์), วันหยุดตลาด
- สำหรับคริปโต ตลาดเปิด 24/7 → ถามว่าอยากให้บอทเทรดตอนเขานอนไหม ถ้าไม่ ให้กำหนดหน้าต่างชัดเจน

## 5. รายการที่บอทห้ามทำเอง (requires_human_confirm)

อิงหลักเดียวกับระบบที่ให้ agent ทำงานแทนคน: **สิ่งที่ย้อนกลับได้ให้ทำอัตโนมัติ สิ่งที่ย้อนกลับไม่ได้ต้องให้คนกด**

| ทำอัตโนมัติได้ | ต้องให้คนยืนยัน |
|---|---|
| อ่านข้อมูลตลาด | เพิ่มขนาดไม้เกินสเปค |
| สร้างสัญญาณ | เพิ่ม leverage |
| เข้าไม้ตามสเปค | ถอนเงินออกจากบัญชี |
| **ตัดขาดทุน** | ปิดหรือลดกำลังของ risk engine |
| ปิดทำกำไรตามสเปค | เทรดนอกหน้าต่างเวลา |
| ลดขนาดไม้ | ปลดล็อก kill switch |

## 6. ตรวจความสอดคล้องก่อนปิดขั้นนี้

ทำทุกข้อ ถ้าข้อไหนไม่ผ่าน ให้บอกผู้ใช้และแก้ก่อน

1. `max_concurrent_positions × risk_per_trade_pct ≤ max_daily_loss_pct` ✓
2. `max_daily_loss_pct × 5 ≥ max_weekly_loss_pct` (ไม่งั้นเพดานสัปดาห์ไม่มีความหมาย) ✓
3. `max_drawdown_pct` ตรงกับ `profile.yaml → pain_threshold.max_drawdown_pct` ✓
4. ระยะ stop ในกลยุทธ์ **กว้างกว่า** ช่วงแกว่งปกติ (ประมาณ 1 ATR) ไม่งั้นจะโดนเขี่ยทุกไม้ ✓
5. ขนาดไม้เล็กสุดที่คำนวณได้ **ไม่ต่ำกว่าขนาดขั้นต่ำของตลาด** ถ้าต่ำกว่า แปลว่าทุนน้อยเกินไปสำหรับสเปคนี้ ต้องบอกตรงๆ ✓

## ผลลัพธ์ที่ต้องส่งมอบ

1. เขียน `bot/risk.yaml`
2. **แสดงตัวอย่างคำนวณจริง 1 ไม้** ด้วยตัวเลขของผู้ใช้เอง ให้เขาเห็นว่าบอทจะซื้อกี่หน่วยและเสี่ยงกี่บาท
3. **แสดงสถานการณ์เลวร้าย** เป็นตัวเลขเงินจริง:
   > "ถ้าแพ้ติดกัน 10 ไม้: เงิน 50,000 เหลือ 47,560 บาท
   >  ถ้าชน kill switch ที่ 15%: เหลือ 42,500 บาท แล้วบอทจะหยุดรอคุณ"
4. อัปเดต `bot/STATUS.md`
5. ชวนไป `/bot:connect`
