# ด่านตรวจ — ก่อนยิงออเดอร์ทุกครั้ง

ด่านนี้คือเหตุผลที่นักเรียนกลับมาแก้กลยุทธ์กี่รอบก็ได้โดยไม่พัง **เครื่องเป็นคนตัดสิน ไม่ใช่คุณ**
หน้าที่คุณคือรันให้ถูก อ่านผลให้ฟังเป็นภาษาคน แล้วพาไปขั้นที่ถูก

## กฎที่ห้ามละเมิด

1. **ห้ามรันอะไรที่มี `--live` กับกลยุทธ์ที่ด่านยังไม่ผ่าน** และต้องรันด่านซ้ำทุกครั้งก่อน `--live`
   (ใช้เวลาไม่กี่วินาที) เพราะผลผ่านผูกกับเนื้อไฟล์กลยุทธ์ แก้ตัวอักษรเดียวก็ต้องตรวจใหม่
2. **ห้ามตัดสินแทนเครื่อง** ถ้ารายงานบอก NOT YET ห้ามพูดว่า "ไม่เป็นไร ไปต่อได้"
3. **ห้ามแก้เทสหรือแก้ตัวตรวจเพื่อให้ผ่าน** ห้ามลบเทสที่ตก ห้ามแก้ `tradebot/cli/check.py`
   ห้ามแก้ `tradebot/risk.py` ถ้าตก ให้แก้กลยุทธ์
4. **ผ่านไม่ได้แปลว่าทำกำไร** พูดประโยคนี้ทุกครั้งที่ผ่าน

## ขั้นตอน

### 1. หาโปรเจคบอทกับกลยุทธ์ที่จะตรวจ

- โปรเจคบอทคือโฟลเดอร์ที่มี `tradebot/` กับ `pyproject.toml` ถ้าไม่เจอ ให้ชวนไป `/bot:scaffold`
- คำสั่งเรียกบอทบน Windows: `.venv\Scripts\tradebot.exe` (ถ้ายังไม่มี `.venv` ให้ทำตาม
  `00-START-HERE.txt` หรือ README ของโปรเจคก่อน)
- กลยุทธ์ที่จะตรวจ: ดูจากตาราง "กลยุทธ์ที่ลอง" ใน `bot/STATUS.md` ถ้าไม่ชัด รัน
  `tradebot --list-strategies` แล้วถามผู้ใช้ด้วย AskUserQuestion
- config: ใช้ `config/testnet.yaml` ถ้ามี (ไฟล์เดียวกับที่จะใช้รันจริงบน testnet)

### 2. รันด่านตรวจ

```
.venv\Scripts\tradebot.exe --config config/testnet.yaml --check --strategy <ชื่อ>
```

exit code 0 = ผ่าน อย่างอื่น = ยังไม่ผ่าน ผลเต็มอยู่ที่ `logs/check-<ชื่อ>.json`

### 3. ถ้าชั้น REPLAY ขึ้นว่า `not run` (ยังไม่มีแท่งเทียนจริง)

รายงานจะบอกคำสั่งดึงแท่งมาให้ เช่น
`tradebot --config config/testnet.yaml --live --fetch-candles --days 1`

- คำสั่งนี้ **อ่านอย่างเดียว ส่งออเดอร์ไม่ได้** แต่ต้องมี `--live` ถึงจะต่อ GRVT ได้
  ไม่ใส่จะได้แท่งปลอมจากตลาดจำลอง (บอทเก็บแยกไว้ใต้ `paper/` ให้แล้ว)
- ต้องมีกุญแจ testnet ใน `config/.env` ก่อน ถ้ายังไม่มี ชวนไป `/bot:connect`
  **ห้ามขอให้ผู้ใช้พิมพ์หรือวางกุญแจในแชท และห้ามเปิดอ่านไฟล์ .env**
- testnet ของ GRVT มีแท่ง 1 นาทีย้อนหลังแค่ราว 1000 แท่ง (ประมาณ 16 ชั่วโมง) ใช้ `--days 1` พอ
- ดึงเสร็จแล้วรันด่านตรวจซ้ำ

### 4. อ่านผลให้ฟัง

สรุปบรรทัดเดียวก่อน: **ผ่าน** หรือ **ยังไม่ผ่าน เพราะ N ข้อ** แล้วอธิบายเฉพาะข้อที่ตก (FAIL)
และข้อเตือน (warn) ด้วยตารางนี้ ใช้คำของคุณเองได้ แต่ความหมายต้องตรง

| ข้อในรายงาน | ความหมาย | แก้ยังไง |
|---|---|---|
| builds from the config | สร้างกลยุทธ์ไม่ได้เลย | อ่าน error ที่ต่อท้าย มักเป็นพารามิเตอร์ผิดใน `__init__` |
| never crashes | มีราคาแบบหนึ่งที่ทำให้โค้ดพัง | ดูชื่อชุดราคาในรายงาน เช่น `flat` มักพังเพราะหารด้วยศูนย์ ให้คืน `None` แทนการพัง |
| no network, no files | กลยุทธ์พยายามต่อเน็ตหรือเปิดไฟล์ | กลยุทธ์อ่านได้แค่ `MarketView` ที่ได้รับ ข้อมูลอื่นต้องส่งเข้ามาทางอื่น |
| fires on test prices (`not run`) | ไม่ยิงเลยแม้แต่ครั้งเดียวบนราคาทดสอบ 12 แบบ | เงื่อนไขอาจแคบเกินจนไม่มีวันจริง ลองอ่านกฎกับผู้ใช้อีกรอบ |
| stop on the losing side | stop อยู่ผิดฝั่ง | ซื้อ = stop ต่ำกว่าราคาเข้า · ขาย = stop สูงกว่าราคาเข้า |
| dated with market.now | สัญญาณใช้เวลาเครื่อง | ใส่ `created_at=market.now` ใน `Signal.build` |
| watches its stop | **ราคาทะลุ stop แล้วไม่ขอปิดไม้** | เพิ่ม `get_exit()` ที่คิด stop จาก `market.position.entry_price` แล้ว `self.stop_hit(...)` ข้อนี้สำคัญที่สุด ตอนรันจริงไม่มีใครตัด stop ให้ |
| same prices, same answers (warn) | ป้อนราคาเดิมได้คำตอบไม่เหมือนเดิม | ใช้ random หรือเวลาเครื่องอยู่ ทดสอบย้อนหลังจะเชื่อไม่ได้ |
| chart() only draws | การวาดเส้นบนบอร์ดไปเปลี่ยนการตัดสินใจ | `chart()` ห้ามแก้ค่าในตัวกลยุทธ์ |
| quiet while holding (warn) | ยิงซ้ำตอนถือไม้อยู่ | `if market.in_position: return None` |
| the strategy's tests | ไม่มีเทส หรือเทสตก | เขียน `tests/test_<ชื่อ>.py` อย่างน้อย 5 เคส (ดู Phase 4 ของ `ai/workflows/strategy-builder.md`) |
| fires on real prices | บนแท่งเทียนจริงไม่ยิงเลย | กฎไม่เคยเป็นจริงกับตลาดนี้ timeframe นี้ |
| some signals get through | ถูกด่านความเสี่ยงปัดตกหมด | ดูรหัสที่ต่อท้าย แล้วใช้ `ai/workflows/debug-refusal.md` |
| stays inside the risk limits (warn) | ทดสอบย้อนหลังแล้วชนเพดานขาดทุน | ไม่ใช่บั๊ก แต่บอกว่ากลยุทธ์นี้เสียเงินเร็วแค่ไหน |
| 30 ticks without an error | รันกับบอทจริงแล้วเจอ error | อ่าน error ที่ต่อท้าย |

### 5. บันทึกลง `bot/STATUS.md`

อัปเดตแถวของกลยุทธ์นี้ในตาราง "กลยุทธ์ที่ลอง" (สร้างตารางถ้ายังไม่มี รูปแบบอยู่ใน `/bot:home`)
ใส่ fingerprint 8 ตัวแรกจากรายงาน ผล (ผ่าน / ยังไม่ผ่าน: ข้อที่ตก) และวันที่
แถวนี้คือสิ่งที่ทำให้แชท AI รอบหน้ารู้ว่าทำถึงไหนแล้ว

### 6. พาไปขั้นต่อไป

ใช้ AskUserQuestion หนึ่งครั้ง **ลอกข้อความนี้ไปใช้ ห้ามแต่งใหม่**

**ถ้ายังไม่ผ่าน**
- หัวข้อคำถาม: `ด่านตรวจยังไม่ผ่าน จะทำอะไรต่อ`
- ตัวเลือก:
  1. `แก้ตามข้อที่ตก` — แก้โค้ดกลยุทธ์ทีละข้อ แล้วรันด่านตรวจใหม่
  2. `กลับไปทบทวนกฎ` — ถ้าข้อที่ตกแปลว่ากฎเองมีปัญหา (ไปที่ `/bot:strategy`)
  3. `อธิบายข้อที่ตกอีกที` — ยังไม่เข้าใจว่าทำไมตก

**ถ้าผ่าน**
- หัวข้อคำถาม: `ผ่านด่านตรวจแล้ว จะทำอะไรต่อ`
- ตัวเลือก:
  1. `รันบน testnet สั้นๆ` — 24 รอบแล้วปิดไม้เอง ดูบนบอร์ดไปพร้อมกัน แล้วต่อด้วย `/bot:review`
  2. `ทดสอบย้อนหลังให้ละเอียด` — ดูตัวเลขกำไรขาดทุน (ไปที่ `/bot:backtest`)
  3. `แก้กลยุทธ์ต่อ` — กลับไปออกแบบ (ไปที่ `/bot:strategy`) แล้วกลับมาที่ด่านนี้อีกครั้ง

คำสั่งรันบน testnet สั้นๆ (รันด่านตรวจซ้ำก่อนทุกครั้ง):

```
.venv\Scripts\tradebot.exe --config config/testnet.yaml --live --strategy <ชื่อ> --iterations 24 --close-at-end
```

`--close-at-end` ปิดไม้ให้ตอนจบ เปิดบอร์ดที่ `http://127.0.0.1:4340/#bot` ไปพร้อมกัน
รันเสร็จให้ชวนไป `/bot:review` ทุกครั้ง
