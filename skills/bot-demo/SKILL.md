# ลองของก่อน — ระบบทดสอบ 10 นาที

คนที่เพิ่งมาถึงมักไม่รู้ว่า "บอทเทรด" แปลว่าอะไรในทางปฏิบัติ อธิบายไปสิบย่อหน้า
ก็ยังนึกไม่ออกเท่ากับได้**เห็นมันทำงานหนึ่งรอบ** ขั้นนี้มีไว้เพื่อสิ่งนั้นอย่างเดียว

จบขั้นนี้เขาจะได้เห็นกับตา: ราคาจริงเข้ามา → กลยุทธ์ออกสัญญาณ → ด่านความเสี่ยงคิดขนาดไม้
→ ออเดอร์ถูกส่ง → ได้ไม้ → บอทปิดไม้เองพร้อมบอกเหตุผล ทั้งหมดด้วย**เงินปลอม**
และ **ไม่ต้องมี API key แม้แต่ตัวเดียว**

## สิ่งที่ต้องพูดก่อนเริ่ม ห้ามข้าม

> "อันนี้คือ**เครื่องทดสอบระบบ ไม่ใช่กลยุทธ์ทำเงิน** มันเข้าออกถี่เพื่อให้เห็นกลไก
> และระยะที่มันเล่นเล็กกว่าค่าธรรมเนียม แปลว่ารันไปนานๆ มันขาดทุนตามค่าธรรมเนียมแน่นอน
> ของจริงจะเริ่มตอน `/bot:profile`"

พูดด้วยคำของตัวเองได้ แต่ **ห้ามข้ามสาระสองข้อนี้**: ไม่ใช่กลยุทธ์ · ขาดทุนโดยออกแบบ
ถ้าผู้ใช้เข้าใจผิดว่านี่คือบอททำเงิน เขาจะเอาไปใส่เงินจริง และนั่นคือความผิดของเรา

## ต้องมีอะไรก่อน

ต้องมีแม่แบบอยู่ในเครื่อง (โฟลเดอร์ที่มี `tradebot/` กับ `config/demo.yaml`)

- **ไม่มี** → เรียก Skill `bot-trade-studio:bot-scaffold` ก่อน แล้วค่อยกลับมา
- **มี** → ตรวจว่า `python -c "import tradebot"` ผ่าน ถ้าไม่ผ่านให้ติดตั้งด้วย `pip install -e .`

ไม่ต้องมี `bot/profile.yaml` ไม่ต้องมีกุญแจ ไม่ต้องต่อโบรกเกอร์

## กลยุทธ์ที่ใช้ — ping_pong

อธิบายสามบรรทัดนี้ให้ผู้ใช้ฟังก่อนรัน อย่ายกศัพท์มาทั้งก้อน

- **เข้าเมื่อ** ราคาหลุดออกจากค่าเฉลี่ย 12 ราคาล่าสุดเกิน 0.03% — หลุดลงไปก็ซื้อ หลุดขึ้นไปก็ขาย
- **ออกเมื่อ** ราคากลับมาที่ค่าเฉลี่ย **หรือ** ชน stop ที่ 0.4% **หรือ** ถือเกิน 3 นาที
- **ทำไมถึงถี่** เพราะ 0.03% คือระยะที่ราคาคริปโตวิ่งผ่านตลอดเวลา ไม่ใช่เพราะมันเก่ง

## คำสั่งที่รัน

```bash
# สามนาที = ประมาณ 2-3 ไม้ กำลังพอดีกับการนั่งดูด้วยกัน
tradebot --dry-run --paper-live --config config/demo.yaml --iterations 36
```

- `--dry-run` ออเดอร์เป็นกระดาษ ไม่มีอะไรถึงตลาดจริง
- `--paper-live` **ราคาจริงจากฟีดสาธารณะของ GRVT** ไม่ต้องใช้กุญแจ
  (ถ้าเน็ตเข้าตลาดไม่ได้ ให้ใช้ `--paper-walk` แทน ราคาจะเป็นของจำลอง แล้วบอกผู้ใช้ด้วยว่าเปลี่ยนไปใช้อะไร)
- ถ้าอยากดูสดๆ ขณะรัน ให้เปิดอีกหน้าต่าง: `node dashboard/server.js --open`
  หรือบอร์ด `cd board` แล้ว `.\start.ps1` แล้วเปิด http://127.0.0.1:4340/#bot
  - **ห้ามบอกให้ใช้ `trunk serve`** — มันเปิดหน้าเว็บได้แต่ไม่เสิร์ฟ `/api/*`
    บอร์ดจะว่างทั้งที่บอทรันอยู่ และนักเรียนจะคิดว่าบอทไม่ทำงาน
  - จบรอบแล้วเปิด http://127.0.0.1:4340/#order บอร์ดจะเล่นซ้ำ tick ที่บอทส่งออเดอร์
    ให้เห็นกลยุทธ์ยิง → ด่านคิดขนาดไม้ → ส่งคำสั่ง เป็นบรรทัดโค้ดที่เดินจริง
    ใช้ภาพนี้ประกอบตอนเล่า audit ทีละจังหวะในหัวข้อถัดไป
  - http://127.0.0.1:4340/#trip เปิดการ์ด "เส้นทางออเดอร์" คู่กับด่านส่งคำสั่ง:
    ตัดสินใจ → ส่ง (ตลาดตอบกี่ ms) → เข้าสมุด → รอจับคู่ → จบ
    **รอบ `/bot:demo` เป็นกระดาษ การ์ดจะขึ้นว่า "จำลอง"** — บอกผู้ใช้ตรงๆ ว่าขั้นเข้าสมุดกับรอจับคู่
    จะเห็นของจริงตอนรันบน testnet (ขั้น 6 ของคู่มือ) อย่าแต่งตัวเลข ms ขึ้นมาเอง

## หลังรันเสร็จ — ส่วนที่สำคัญที่สุด

**อ่าน `logs/audit.jsonl` แล้วเล่าให้ฟังทีละบรรทัด ห้ามบอกให้เขาไปเปิดอ่านเอง**

ยกบรรทัดจริงมาแปลเป็นภาษาคน อย่างน้อยให้ครบห้าจังหวะนี้:

| จังหวะ | สิ่งที่ต้องชี้ให้เห็น |
|---|---|
| เงียบ | บรรทัดที่มีแต่ราคา = บอทดูแล้วไม่ทำอะไร **นี่คือสถานะปกติของบอทที่ทำงานถูกต้อง** |
| สัญญาณ | `signal` พร้อม `reason` ที่อ่านออก — กลยุทธ์ขออะไร ที่ราคาเท่าไร stop ตรงไหน |
| ด่าน | `order.qty` มาจากไหน — ความเสี่ยงต่อไม้ ÷ (ระยะ stop + ค่าธรรมเนียมขาเข้าและขาออกต่อหน่วย) ไม่ใช่ "ซื้อเท่าที่มีเงิน" |
| ได้ไม้ | `receipt.simulated: true` — ย้ำว่าเป็นกระดาษ |
| ปิด | `exit.reason` — บอทปิดเองเพราะอะไร |

ถ้ามี `reject` ในรอบนั้น **ยิ่งดี** เอามาอธิบายเลยว่าด่านปฏิเสธเพราะอะไร
(ดู `/bot:explain` หรือ `references/reject-codes.md` ถ้ามี) การได้เห็นด่านทำงาน
มีค่ากับเขามากกว่าการได้เห็นออเดอร์ผ่าน

จบด้วยตัวเลขจริงหนึ่งบรรทัด เช่น "สามนาที ได้ 2 ไม้ กำไรขาดทุนรวม -15.78 USDT ซึ่งคือค่าธรรมเนียมกับจังหวะที่เดาผิด"

## ถ้าเขาอยากให้มันรันทิ้งไว้

```bash
# บนเครื่องตัวเอง
docker build -t tradebot .
docker run --rm tradebot

# บน Railway
# ชี้ Railway มาที่รีโปนี้ มันอ่าน Dockerfile เอง คำสั่งตั้งต้นคือโหมดลองของนี่แหละ
# ไม่ต้องใส่ตัวแปรลับอะไรเลยเพราะโหมดนี้ไม่ใช้กุญแจ
```

เตือนสองข้อ:

- บน Railway ดิสก์หายทุกครั้งที่ deploy ใหม่ `logs/` กับ `state.json` จึงไม่ถาวร
  (ของจริงต้อง mount volume ที่ `/app/logs`)
- **อย่าเอา image นี้ไปรันกับกุญแจจริงโดยไม่เปลี่ยนคำสั่ง** คำสั่งตั้งต้นคือโหมดกระดาษ
  และควรเป็นแบบนั้นต่อไปจนกว่าจะผ่าน `/bot:deploy`

## ปิดท้าย — พาไปขั้นต่อไป

ใช้ AskUserQuestion หนึ่งครั้ง **ลอกข้อความนี้ไปใช้ ห้ามแต่งใหม่**

- หัวข้อคำถาม: `เห็นระบบทำงานแล้ว อยากทำอะไรต่อ`
- ตัวเลือก:
  1. `เริ่มสร้างบอทของตัวเอง` — ตอบคำถามเรื่องทุนกับความเสี่ยงก่อน แล้วค่อยเลือกกลยุทธ์ (ไปที่ `/bot:profile`)
  2. `ดูอีกรอบ` — รันซ้ำอีกสามนาที คราวนี้เปิดแดชบอร์ดดูไปพร้อมกัน
  3. `อยากเข้าใจศัพท์ก่อน` — ถามคำที่ยังไม่เข้าใจทีละคำ (ไปที่ `/bot:explain`)
  4. `เอาไปรันทิ้งไว้ก่อน` — docker หรือ Railway ตามข้างบน

ต่อท้ายได้หนึ่งประโยคที่โยงกับสิ่งที่เพิ่งเห็น เช่น "ไม้ที่สองโดนลากไป 105 วินาทีก่อนปิด
ถ้าอยากให้บอทของคุณทนลากได้นานแค่ไหน เดี๋ยวคุยกันในขั้นความเสี่ยง"

## สิ่งที่ห้ามทำในขั้นนี้

- ห้ามเสนอให้ใส่กุญแจจริงหรือ `--live` ไม่ว่าเขาจะขอแค่ไหน (ชี้ไปที่ `/bot:deploy`)
- ห้ามปรับพารามิเตอร์ของ ping_pong ให้ "ดูดีขึ้น" มันไม่ใช่กลยุทธ์ การจูนมันคือการสอนผิด
- ห้ามเอาผลสามนาทีไปสรุปว่ากลยุทธ์ไหนดีหรือไม่ดี
