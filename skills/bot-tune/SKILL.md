# ปรับจูนอย่างมีวินัย

> การปรับจูนเป็นวิธีทำลายบอทที่พบบ่อยที่สุด
> ทุกครั้งที่ปรับแล้วดูผลย้อนหลัง คุณกำลังแอบใส่ข้อมูลอนาคตเข้าไปในกลยุทธ์ทีละนิด

## ด่านที่ 1 — ทำไมถึงจะปรับ (ต้องผ่านก่อนทำอะไรทั้งสิ้น)

ถามผู้ใช้ว่าเหตุผลคืออะไร แล้วจัดหมวด:

| เหตุผล | ให้ปรับไหม |
|---|---|
| "บอทขาดทุนมาหลายเดือน" | ❌ **ไม่** ถ้า drawdown ยังอยู่ในช่วงที่ backtest เคยเจอ นี่คือระบบทำงานถูกต้อง |
| "ค่านี้ดูไม่สวย อยากลองค่าอื่น" | ❌ **ไม่** นี่คือการเดาสุ่ม |
| "เห็นว่าค่า 25 ให้ผล backtest ดีกว่า 20" | ❌ **ไม่** นี่คือ overfitting ตรงๆ |
| "พบบั๊ก: stop คำนวณผิดสูตร" | ✅ ใช่ นี่คือแก้บั๊ก ไม่ใช่จูน — ไปแก้แล้วรัน backtest ใหม่ทั้งชุด |
| "ตลาดเปลี่ยนโครงสร้างจริง (ค่าธรรมเนียมเปลี่ยน, tick size เปลี่ยน, เอ็กซ์เชนจ์เปลี่ยนกติกา)" | ✅ ใช่ ปรับให้ตรงความจริงใหม่ |
| "พฤติกรรมจริงไม่ตรงสเปค (slippage จริงสูงกว่าสมมติ 3 เท่า)" | ✅ ใช่ ปรับสมมติฐานให้ตรงความจริง |
| "ทุนเปลี่ยน / เป้าหมายชีวิตเปลี่ยน" | ✅ ใช่ แต่ไปที่ `/bot:profile` และ `/bot:risk` ไม่ใช่ที่นี่ |

**ถ้าเหตุผลอยู่ในกลุ่ม ❌ ให้ปฏิเสธอย่างสุภาพแต่ชัดเจน** และอธิบายว่าทำไมการปรับตอนนี้จะทำให้แย่ลง

## ด่านที่ 2 — นับจำนวนครั้ง

อ่าน `bot/STATUS.md` ดูว่าปรับไปกี่รอบแล้ว

- **เกิน 3 รอบต่อปี** → เตือนว่ากำลังเข้าสู่วงจร fit ข้อมูล
- **เกิน 6 รอบต่อปี** → บอกตรงๆ ว่ากลยุทธ์นี้น่าจะไม่เคยมีขอบจริงตั้งแต่ต้น ควรกลับไป `/bot:strategy` มากกว่าปรับต่อ

## ด่านที่ 3 — กติกาการปรับ

1. **เขียนสมมติฐานก่อนแตะตัวเลข** ลง `bot/journal/` ว่า
   "ฉันเชื่อว่า X เพราะ Y ถ้าฉันถูก ผลที่ควรเห็นคือ Z ถ้าผลไม่เป็น Z ฉันจะย้อนกลับ"
   **เขียนก่อน** ไม่ใช่เขียนหลังเห็นผล
2. **ปรับทีละตัวแปร** เปลี่ยนสองอย่างพร้อมกันแล้วดีขึ้น = ไม่รู้ว่าตัวไหนช่วย
3. **ดูการไล่ค่า ไม่ใช่ค่าเดียว** ถ้าเปลี่ยนจาก 20 เป็น 25 ต้องดูผลของ 18–30 ทั้งช่วง
   เลือกค่าที่อยู่กลาง **ที่ราบสูง** ไม่ใช่ยอดแหลม — ยอดแหลมคือความบังเอิญ
4. **ทดสอบบน out-of-sample ที่ยังไม่เคยแตะ** ถ้าใช้หมดแล้ว ต้องรอข้อมูลใหม่สะสม ไม่มีทางลัด
5. **เปลี่ยนแล้วต้องกลับไป paper อีกรอบ** อย่างน้อย 2 สัปดาห์ ก่อนใช้เงินจริง
6. **เวอร์ชันสเปค** เก็บไฟล์เก่าไว้เป็น `strategy.v1.yaml` ไม่ใช่เขียนทับ

## ด่านที่ 4 — เกณฑ์ย้อนกลับ

กำหนดไว้ล่วงหน้าว่าถ้าเกิดอะไรจะย้อนไปเวอร์ชันเดิม เช่น
> "ถ้าผ่านไป 20 ไม้แล้วยังแย่กว่าเวอร์ชันเดิม ให้ย้อนกลับ"

เขียนลงไฟล์ ไม่ใช่จำเอา

## สิ่งที่ปรับได้โดยไม่นับเป็นการจูน

ปรับได้เลย ไม่ต้องผ่านด่าน เพราะเป็นการทำให้ปลอดภัยขึ้น:

- **ลด** ขนาดไม้
- **ลด** จำนวนไม้พร้อมกัน
- **ลด** เพดาน leverage
- **เข้มขึ้น** กับเพดานขาดทุน
- เพิ่มช่วงเวลาห้ามเทรด
- เพิ่มรายการที่ต้องให้คนยืนยัน

การทำให้ระบบเสี่ยงน้อยลงไม่เคยเป็นการ overfit

## ผลลัพธ์ที่ต้องส่งมอบ

1. บันทึกสมมติฐาน เหตุผล และเกณฑ์ย้อนกลับลง `bot/journal/`
2. สำเนาสเปคเก่าเก็บเป็นเวอร์ชัน
3. ตารางไล่ค่าพารามิเตอร์ ไม่ใช่ค่าเดียว
4. อัปเดตตัวนับจำนวนครั้งที่ปรับใน `bot/STATUS.md`
5. ชวนกลับไป `/bot:backtest` แล้ว `/bot:paper`
