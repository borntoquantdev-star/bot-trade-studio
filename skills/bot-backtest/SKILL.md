# ขั้นที่ 5 — ทดสอบย้อนหลัง

> **backtest ไม่ได้บอกว่าอนาคตจะกำไร** มันบอกแค่ว่า "ถ้าในอดีตทำแบบนี้จะเกิดอะไร"
> ประโยชน์จริงของมันคือ **คัดกลยุทธ์ที่แย่ทิ้ง** ไม่ใช่ยืนยันว่ากลยุทธ์ดี

## ก่อนรัน — แบ่งข้อมูลให้ถูก

```
ข้อมูลทั้งหมด
├── In-sample (60%)   ← ใช้ออกแบบและจูนได้
├── Out-of-sample (20%) ← ห้ามดูจนกว่าจะจูนเสร็จ ดูได้ครั้งเดียว
└── Holdout (20%)     ← ล็อกไว้ ดูตอนก่อนขึ้นเงินจริงเท่านั้น
```

ถ้าผู้ใช้จูนแล้วไปดู out-of-sample แล้วกลับมาจูนอีก **out-of-sample นั้นตายแล้ว** กลายเป็น in-sample ไปโดยปริยาย
ต้องบอกเขาตรงๆ และนับจำนวนครั้งที่เขาเปิดดูไว้ใน `bot/STATUS.md`

## ต้องใส่ต้นทุนจริงเสมอ

backtest ที่ไม่หักต้นทุนคือนิยาย ใส่ให้ครบ:

- ค่าธรรมเนียม maker/taker หรือค่าคอมฯ ทั้งขาเข้าและขาออก
- spread (ราคาซื้อ-ขายต่างกัน)
- slippage ที่สมเหตุผล — อย่างน้อย 1 tick สำหรับ limit, 2–5 tick สำหรับ market
- ค่า funding / swap ถ้าถือข้ามคืน
- ภาษี ถ้าเกี่ยวข้อง

> ถ้าหักต้นทุนแล้วกำไรหายไปเกินครึ่ง แปลว่ากลยุทธ์เทรดถี่เกินไปสำหรับทุนขนาดนี้

## รายงานผล — ต้องมีครบ 12 ตัว

ห้ามรายงานแค่ "กำไร X%" เด็ดขาด

| ตัววัด | ทำไมต้องมี |
|---|---|
| ผลตอบแทนทบต้นต่อปี (CAGR) | ผลตอบแทนที่เทียบข้ามช่วงเวลาได้ |
| **ขาดทุนสูงสุดจากจุดสูงสุด (max drawdown)** | ตัวที่สำคัญกว่ากำไร |
| **ระยะเวลาที่จมอยู่ใต้จุดสูงสุด** | กี่เดือนที่ต้องทนเห็นพอร์ตติดลบ |
| จำนวนไม้ทั้งหมด | ต่ำกว่า 100 ไม้ = สถิติไม่มีความหมาย |
| อัตราชนะ | ดูคู่กับตัวถัดไปเสมอ ลำพังมันหลอก |
| อัตราส่วนกำไรต่อขาดทุนเฉลี่ย | ชนะ 35% ก็กำไรได้ถ้าตัวนี้ > 2 |
| Profit factor | กำไรรวม ÷ ขาดทุนรวม ต่ำกว่า 1.3 = เปราะ |
| Sharpe / Sortino | ผลตอบแทนเทียบความเหวี่ยง |
| เดือนที่แย่ที่สุด | ตัวเลขที่ผู้ใช้จะต้องเจอจริง |
| แพ้ติดกันสูงสุดกี่ไม้ | ใช้ทดสอบใจผู้ใช้ |
| ต้นทุนรวมที่จ่ายไป | เทียบกับกำไรสุทธิ |
| **เทียบกับซื้อแล้วถือเฉยๆ** | ถ้าแพ้ buy & hold แปลว่าความซับซ้อนทั้งหมดนี้ไม่คุ้ม |

## แปลผลเป็นภาษาคน — นี่คือหน้าที่หลักของคุณ

อย่าทิ้งตารางตัวเลขให้ผู้ใช้ตีความเอง **แปลเป็นประสบการณ์ที่เขาจะเจอ**

ตัวอย่างที่ถูก:
> "ถ้าคุณเริ่มด้วย 50,000 บาทเมื่อต้นปี 2021 วันนี้จะมีประมาณ 81,000 บาท
>
> แต่ระหว่างทางมีช่วงที่เจ็บจริง: **เดือนพฤษภาคมถึงธันวาคม 2022 คุณจะขาดทุนติดกัน 8 เดือน และเห็นพอร์ตลดจาก 72,000 เหลือ 54,000 บาท (−25%)** แปดเดือนนั้นคุณจะเปิดดูทุกวันแล้วสงสัยว่าบอทพังหรือเปล่า
>
> บอทเทรดทั้งหมด 147 ไม้ แพ้ 92 ไม้ ชนะ 55 ไม้ — **คุณจะเห็นไฟแดงบ่อยกว่าไฟเขียว** แต่ไม้ที่ชนะเฉลี่ยใหญ่กว่าไม้ที่แพ้ 2.8 เท่า
>
> ซื้อ BTC แล้วถือเฉยๆ ช่วงเดียวกันได้ 94,000 บาท — **มากกว่าบอท** แต่ต้องทน drawdown 64% ระหว่างทาง บอทแลกกำไรที่น้อยกว่ากับความเจ็บที่น้อยกว่าครึ่ง"

แล้วถามคำถามปิด:
> **"ขาดทุนติดกัน 8 เดือน เห็นพอร์ตลด 25% คุณจะยังปล่อยให้บอทรันต่อไหม"**
> ถ้าตอบว่าไม่ → กลยุทธ์นี้ไม่เหมาะกับเขา ต้องกลับไป `/bot:strategy` ไม่ใช่ไปจูนตัวเลข

## ตรวจ overfitting — 7 สัญญาณอันตราย

ยิ่งเข้าหลายข้อ ยิ่งน่าจะเป็นการ fit ข้อมูลเก่า ไม่ใช่กลยุทธ์จริง

| สัญญาณ | เกณฑ์ |
|---|---|
| 1. พารามิเตอร์เยอะเกิน | เกิน 5 ตัวที่ปรับได้ |
| 2. ไม้น้อยเกิน | ต่ำกว่า 100 ไม้ หรือต่ำกว่า 30 ไม้ต่อปี |
| 3. ทดสอบช่วงเดียว | ไม่ได้ลองหลายช่วงตลาด (ขาขึ้น ขาลง ออกข้าง) |
| 4. **เปราะต่อพารามิเตอร์** | เปลี่ยนค่าจาก 20 เป็น 21 แล้วผลเปลี่ยนเกิน 30% |
| 5. ดีเกินจริง | Sharpe > 3 หรือ max DD < 5% บนกลยุทธ์เทรด |
| 6. กำไรกระจุก | กำไรทั้งหมดมาจาก 1–2 ไม้ ถ้าตัดออกแล้วขาดทุน |
| 7. จูนหลายรอบ | ปรับพารามิเตอร์แล้วรันซ้ำเกิน 10 ครั้ง |

### ทดสอบความทนทาน (ต้องทำ ไม่ใช่ทางเลือก)

1. **ไล่พารามิเตอร์รอบๆ ค่าที่เลือก** — ถ้าค่า 18, 20, 22 ให้ผลใกล้เคียงกัน = ทนทาน / ถ้า 20 ดีแต่ 19 กับ 21 ขาดทุน = fit
2. **เลื่อนหน้าต่างเวลา (walk-forward)** — จูนบน 2 ปี ทดสอบบน 6 เดือนถัดไป แล้วเลื่อนไปเรื่อยๆ ผลรวมคือตัวเลขที่เชื่อได้มากกว่า
3. **เปลี่ยนวันเริ่ม** — เริ่มช้ากว่าเดิม 1 เดือน ผลควรใกล้เคียงกัน
4. **ทดสอบกับสินทรัพย์อื่น** — กลยุทธ์ที่จริงมักใช้ได้กับตัวอื่นในตลาดเดียวกันบ้าง

## เกณฑ์ผ่าน — ต้องครบทุกข้อถึงไปขั้นเทรดกระดาษได้

1. ✅ จำนวนไม้ ≥ 100 (หรือ ≥ 3 ปีสำหรับกลยุทธ์ rebalance)
2. ✅ Profit factor ≥ 1.3 **หลังหักต้นทุนครบ**
3. ✅ max drawdown ≤ เพดานใน `profile.yaml`
4. ✅ ผ่านการไล่พารามิเตอร์ — ค่าข้างเคียงยังกำไร
5. ✅ ผลบน out-of-sample ไม่แย่กว่า in-sample เกิน 40%
6. ✅ ตัดไม้ที่ดีที่สุด 2 ไม้ออกแล้วยังกำไร
7. ✅ **ผู้ใช้ตอบว่ารับช่วง drawdown ที่เห็นได้จริง**

ถ้าไม่ผ่านข้อไหน ให้บอกชัดว่าข้อไหน และ **ห้ามแนะนำให้จูนตัวเลขเพื่อให้ผ่าน** — ให้กลับไปทบทวนกลยุทธ์หรือยอมรับว่ามันใช้ไม่ได้

## ผลลัพธ์ที่ต้องส่งมอบ

1. เขียน `bot/reports/backtest-YYYY-MM-DD.md` — ตาราง 12 ตัว + คำอธิบายภาษาคน + ผลตรวจ overfit
2. ถ้ามีกราฟ ให้ทำเส้นทุน (equity curve) และเส้น drawdown
3. สรุปว่า **ผ่าน / ไม่ผ่าน** พร้อมเหตุผล
4. อัปเดต `bot/STATUS.md` — บันทึกว่าเปิดดู out-of-sample ไปกี่ครั้งแล้ว
5. ผ่านแล้วชวนไป `/bot:paper` / ไม่ผ่านชวนกลับ `/bot:strategy` หรือเรียก `/bot:reality-check`
